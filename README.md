# UniFit

UniFit is a Flask web app that builds a weekly workout plan from your height, weight, age, experience, goal and equipment, and picks a starting weight for every lift. It can also send reminders to your phone or browser through Firebase Cloud Messaging.

It grew out of a hackathon project where a team of students generated 10,000 synthetic rows of height and weight data and trained a random forest in a notebook to predict exercise weights. That version was a notebook and a CSV. This one is a working application: a Flask API, a stored model, a routine engine, a responsive front end, and push notifications.

## What it does

- **Personalized routines.** Enter age, height, weight, sex and experience, then choose a goal (build muscle, get stronger, lose fat), 2 to 6 training days, session length, equipment (full gym, dumbbells, or none) and up to two focus areas. The engine picks a split, chooses exercises that fit your equipment and time, and sets sets, reps and rest for your goal.
- **Starting weights from a model.** A random forest predicts a working weight for each lifted exercise from your body measurements. Barbell lifts also show which plates to load on each side, and the barbell at the top of the page loads with those plates.
- **Reminders.** Pick a time and the server sends a notification on your training days naming that day's workout, and optionally a short note on rest days. Times follow your own timezone.
- **Responsive front end.** Plain HTML, CSS and JavaScript with no build step, self-hosted fonts, keyboard navigation, and reduced-motion support. It works from a 320px phone to a wide desktop.

## Run it

Requires Python 3.10 or newer.

```
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Open http://127.0.0.1:5000. The first start trains the model (10 to 15 seconds) and saves it to `data/model.joblib`. To retrain and write the dataset to `data/synthetic_workouts.csv`:

```
python -m unifit.train
```

Without any Firebase settings the reminder feature runs in preview mode: the schedule is saved and the **Send a test** button shows the notification on screen, but nothing is delivered to a device.

## The model

The training data is synthetic. Real lifting logs that pair body measurements with working weights are hard to get, so `unifit/data_gen.py` generates 15,000 rows from a strength formula:

```
load = reference load for the exercise
     x (body weight / 170 lb) ^ 0.67        strength grows with body size
     x sex factor                            upper body 0.62, lower body 0.78 for women
     x age factor                            flat to 30, then 0.8% lower per year
     x experience factor                     1.0, 1.45, 1.9
     x random noise (about 9%)
```

Rounded to 2.5 lb and floored at the lightest weight each exercise can be loaded with. Heights range from 48 to 80 inches. Six variables go in (height, weight, age, sex, experience, exercise) and one comes out (working weight in pounds).

A scikit-learn pipeline (one-hot encoding plus a `RandomForestRegressor` with 200 trees) trains on 12,000 rows and is scored on 3,000 held-out rows. The live metrics are shown in the page footer and returned by `/api/model-info`.

These numbers say the model recovered the formula it was trained on. They say nothing about how well the weights fit real people, because no real people are in the data. Treat the output as a sensible place to start a first set, which is also how the app presents it. Every plan includes that caveat.

## Push notifications with Firebase

Reminders go through Firebase Cloud Messaging. A browser registers a token, the server stores it with the reminder time and timezone, and a scheduler thread checks every minute for devices that are due. A device that is no longer reachable (the token was revoked or expired) is removed automatically.

To turn on real delivery:

1. Create a project in the [Firebase console](https://console.firebase.google.com) and add a web app. Copy its config values.
2. In Project settings, Cloud Messaging, Web Push certificates, generate a key pair. This is the VAPID key.
3. In Project settings, Service accounts, generate a private key and save the JSON file somewhere outside the repo.
4. Copy `.env.example` to `.env` and fill in the values. Set `FIREBASE_CREDENTIALS` to the path of the JSON key.
5. Restart `python run.py`. The reminders panel stops saying "preview" and asks for notification permission.

Browsers only allow push on `https://` pages or `localhost`. For a deployed copy, set `UNIFIT_APP_URL` to the public https address so tapping a notification opens the app.

The service worker at `/firebase-messaging-sw.js` is generated by the server from your environment settings, so no keys are committed to the repo. Service account keys, `.env` and everything under `data/` are ignored by `.gitignore`.

Delivery to a real device is not exercised by the tests, since that needs your own Firebase project. What is tested: the scheduler (timezones, grace window, one message per day, retry after failure, token cleanup), the API, and the Firebase sender with the SDK mocked.

## API

| Method and path | Purpose |
| --- | --- |
| `POST /api/routine` | Build a plan from a profile (JSON). Returns 400 with per-field messages for bad input. |
| `GET /api/model-info` | Training metrics for the loaded model. |
| `GET /api/health` | Liveness, and whether pushes are sent through Firebase or previewed. |
| `GET /api/firebase-config` | Browser-side Firebase settings, when configured. |
| `POST /api/notifications/register` | Save a device token with reminder time, timezone and schedule. |
| `DELETE /api/notifications/register` | Remove a device. |
| `POST /api/notifications/test` | Send one notification to a registered device now. |

Example:

```
curl -s localhost:5000/api/routine -H 'Content-Type: application/json' -d '{
  "age": 21, "height_in": 70, "weight_lb": 165, "sex": "male", "experience": "beginner",
  "goal": "hypertrophy", "days_per_week": 4, "equipment": "gym", "session_minutes": 60,
  "focus": ["arms"]
}'
```

## Tests

```
pip install -r requirements-dev.txt
pytest
```

The suite covers the data generator (ranges, determinism, the strength formula), the model (metrics, predictions that move the right way with experience, size and sex, save and load), the routine engine (every split, equipment limit, goal, plate math), the API through Flask's test client, the reminder scheduler, and the Firebase sender with the SDK mocked. GitHub Actions runs it on every push. The front end has no automated tests.

## Limitations

- US units only (pounds and inches).
- No accounts. A browser's push token is its identity, and the reminder schedule is whatever that browser last registered.
- The scheduler runs inside the web process, so run one instance. It checks every minute and skips a reminder that is more than two hours late.
- The plan doesn't track completed workouts or adjust weights week to week.
- The test-notification rate limit is kept in memory.
- Muscle-group choices and exercise selection are rules in `unifit/routines.py`, not learned. Only the starting weights come from the model.

## Layout

```
unifit/
  exercises.py       exercise catalog: muscle, equipment, reference loads, form cues
  data_gen.py        synthetic dataset
  model.py           training, evaluation, saving, predictions
  routines.py        profile validation, splits, exercise selection, prescriptions, plates
  notifications.py   Firebase and dry-run senders, reminder scheduler
  store.py           SQLite storage for registered devices
  app.py             Flask app and API
static/              HTML, CSS, JavaScript, fonts (Archivo and Atkinson Hyperlegible, SIL OFL)
tests/               pytest suite
run.py               start the server
```
